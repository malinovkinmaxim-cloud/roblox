# THE DOPPELGÄNGER OBBY

Multiplayer-obby для Roblox, в котором главный игровой элемент — **точная копия игрока (Doppelgänger)**.
На каждом уровне двойник получает роль: Echo (следует за тобой), Rival (соревнуется с тобой), Shadow (повторяет твои действия с задержкой), Ally (помогает по команде) или Troll (притворяется союзником).
Каждый уровень задаёт вопрос: *«Как мне использовать своего двойника?»* или *«Как мне пережить то, что он делает?»*

---

## Как запустить

### Вариант 1 — открыть готовое место
Открой `DoppelgangerObby.rbxlx` в Roblox Studio и нажми **Play**.

> Файл сгенерирован из `src/` командой `rojo build`. После правок кода пересобери его (см. ниже)
> или работай через Rojo-синхронизацию.

### Вариант 2 — Rojo (рекомендуется для разработки)
1. Установи [Rojo](https://rojo.space) 7.x и плагин Rojo для Studio.
2. `rojo serve` в корне репозитория → в Studio: плагин Rojo → **Connect**.
3. Пересборка файла места: `rojo build default.project.json -o DoppelgangerObby.rbxlx`.

### Сохранения в Studio
Чтобы проверить DataStore в Studio: *Game Settings → Security → Enable Studio Access to API Services* (место должно быть опубликовано).
Без этого игра работает в режиме «память без сохранения» и честно пишет об этом в настройках.

### Управление
| | Способность (ABILITY) | Взаимодействие (INTERACT) |
|---|---|---|
| ПК | `Q` | `E` |
| Геймпад | `Y` | `X` |
| Телефон / планшет | кнопка ABILITY | кнопка INTERACT |

Способности зависят от роли: Shadow — **FREEZE / RELEASE** (заморозить тень на месте), Ally/Troll — **SEND / RECALL** (отправить двойника туда, куда смотришь, и позвать обратно).

### Ключевые решения
* **Каждый игрок играет в своей копии уровня.** Двери, кнопки и двойники разных игроков не мешают друг другу. Уровни стоят в Workspace.ActiveLevels рядами по оси Z.
* **Сервер решает всё важное:** старт, время, смерти, чекпоинты, финиш, роль, награды. Клиент только рисует UI и отправляет «нажал Q/E». Каждый RemoteEvent проверяет типы, частоту (rate limit) и состояние.
* **Двойник кинематический.** Это R15-риг с внешностью игрока. Его ведёт `AlignPosition`/`AlignOrientation` (Rigidity), а не `Humanoid:MoveTo`. Поэтому Shadow повторяет путь игрока точно, двойник не застревает в pathfinding, а на клиентах движение гладко интерполируется. При этом он честно взаимодействует с миром:
  * закрытая дверь его останавливает (blockcast по дверям);
  * если под ним нет пола (фейковая или исчезнувшая платформа, промах), он падает;
  * кнопки, плиты, лазеры и финиш работают для него через тот же InteractionService, что и для игрока.
* **Минимум циклов:** 3 Heartbeat-подключения на весь сервер (Interaction, Obstacle, Doppelganger), а не по одному на объект. Вращающиеся балки анимируются на клиенте по серверному времени, а попадание сервер считает математически, так что сеть не расходуется.
* **Уровни — это данные.** Новый уровень = новый ModuleScript в `ServerStorage.Levels`. Код менять не нужно.

## Роли

| Роль | Поведение | Как работает |
|---|---|---|
| **Echo** (Follower) | идёт твоими шагами в 6 студах позади | воспроизводит запись твоего пути; нажимает всё, по чему ты прошёл |
| **Rival** | бежит к финишу по маршруту уровня | чуть быстрее тебя (×1.1), но ошибается: колеблется, выбирает случайные развилки, иногда промахивается и падает, иногда лезет под лазер. Резинка: замедляется, если сильно впереди. Никогда не застревает: у закрытых дверей есть таймаут и запасные ветки маршрута |
| **Shadow** | повторяет твои действия с задержкой (0.7 с, настраивается) | запись 15 снимков/с (позиция, поворот, прыжок, земля). Нажимает твои кнопки позже, попадает под лазеры, которые ты прошёл вовремя, падает с платформ, которые исчезли. У закрытой двери ждёт, потом догоняет (×1.6) или «глитчем» проходит сквозь неё. Способность **FREEZE** (с уровня 7) |
| **Ally** | помогает, но только по команде | **SEND**: повернись к кнопке, плите или платформе и нажми ABILITY, двойник полетит туда и будет держать её. **RECALL**: зови обратно. Отправленный на фейковую платформу, падает вместо тебя |
| **Troll** | притворяется Ally | предаёт: идёт к другой цели (любит кнопки-ловушки), бросает плиту, заманивает на фейковые платформы. Но всегда честно выдаёт себя: колеблется перед командой, контур вспыхивает пурпурным, фейковые платформы под ним мерцают |

Новая роль = модуль в `src/server/Roles/` + запись в `RoleConfig.lua`. RoleService находит её сам.
Шансы для случайных ролей: `Config.ROLE_CHANCES`.

### Как добавить уровень
Создай `src/levels/Level13.lua`:

```lua
local K = require(game:GetService("ServerScriptService").Server.Level.LevelKit)

return K.Level({
	Id = 13,
	Name = "MY LEVEL",
	Subtitle = "Short description",
	ParTime = 60,                 -- время для Time Bonus
	Role = "Shadow",              -- или { Pool = { "Ally", "Troll" } } для случайной роли
	-- RoleHidden = true,         -- показывать "???" до раскрытия
	-- ShadowDelay = 1.0, AllowFreeze = true, ShadowOffset = Vector3.new(0,0,-26), LinkedFate = true

	Elements = {
		K.Start(0, 0, 0),                                   -- y = высота верха пола
		K.Floor(20, 0, 0, 26, 8),                           -- x, y, z, ширина по X, по Z
		K.Button("B1", 18, 0, 0, { Activator = "Doppel", Mode = "Timed", Duration = 4, Targets = { "D1" } }),
		K.Gate("D1", 30, 0, 0, 8, 10),                      -- дверь с косяками
		K.Checkpoint(1, 40, 0, 0),
		K.Finish(60, 0, 0),
	},
	-- Route = { K.Node(...), ... }                       -- нужен для Rival / (опционально) других AI
})
```

Правила геометрии: игрок бежит со скоростью 16 студ/с, высота прыжка 7.2. Комфортные разрывы — до 7 студов, подъём — до 4.
Уровень идёт вдоль **+X**. Все элементы перечислены в `LevelKit.lua` с комментариями: пол, стена, kill brick, лазер (мигающий или ловушка), вращающаяся балка, движущаяся платформа (линейная/вертикальная/круговая, опционально с питанием от кнопки), исчезающая, падающая и фейковая платформы, launch pad, teleport pad, кнопка, плита, дверь, мост, табличка.
Проверка: `lune run tests/run.luau`. Тест проверит данные, маршрут Rival, пол под каждой точкой маршрута, перекрытия полов и прогонит Rival по уровню на 20 сидах.

## Тесты

Офлайн-тесты запускаются в [Lune](https://lune-org.github.io) без Roblox:

```
lune run tests/run.luau
```

Что проверяется (81 тест):
* все 12 уровней загружаются и проходят `LevelValidator` (id, роли, связи кнопка → дверь, чекпоинты 1..N, маршруты);
* под каждой точкой маршрута Rival есть пол, из любой точки маршрута можно дойти до финиша, прыжки в маршруте не длиннее 16 студов;
* нет совпадающих перекрытых полов (z-fighting), финиш впереди старта;
* **симуляция Rival** на реальных данных уровней 2, 4, 9, 10 (20 сидов каждый): Rival всегда доходит до финиша — с фейковыми платформами, закрытыми дверями, кнопкой-ловушкой, исчезающими и движущимися платформами;
* **симуляция Shadow**: повторяет игрока ровно с задержкой; ждёт у закрытой двери и догоняет, когда она открывается; проходит сквозь дверь, которая не открывается;
* TrailRecorder (интерполяция, телепорты, обрезка буфера, «на N студов позади»), награды, XP-прогрессия, движение платформ.

Дополнительно весь код проверяется `luau-lsp analyze` с типами Roblox API и собирается `rojo build`.

### Что проверено, а что нужно проверить в Studio
Код ни разу не запускался в движке Roblox: в среде разработки его нет. Проверено статически (анализ типов, сборка) и офлайн-тестами логики и ИИ.
Перед публикацией стоит пройти в Studio этот чек-лист (тесты из ТЗ):

1. Игрок умирает (kill brick, лазер, балка, падение в пустоту, кнопка Reset) → экран «YOU DIED» → респаун на чекпоинте.
2. Двойник умирает (лазер, фейковая платформа) → через ~1.4 с появляется снова.
3. При респауне игрока двойник тоже переносится к чекпоинту (для Rival — на узел этого чекпоинта).
4. Чекпоинты: счётчик в HUD, зелёный флаг, монеты при первом прохождении.
5. Shadow (уровни 5–8): повторяет прыжки и нажимает кнопки с задержкой; FREEZE на уровне 7.
6. Rival (уровни 2, 4, 9, 10): бежит, ошибается, статус «DOPPELGÄNGER IS AHEAD!».
7. Двери и плиты: плавное открытие/закрытие.
8. Несколько игроков одновременно (Studio → Test → 2–3 Players): у каждого своя копия уровня.
9. Выход игрока посреди уровня: копия уровня удаляется.
10. Завершение уровня: экран результатов, монеты и XP в профиле.
11. DataStore: с включённым доступом к API данные сохраняются между сессиями.
12. Мобильный UI: Studio → Device Emulator (телефон): кнопки ABILITY/INTERACT, масштаб интерфейса.

На что смотреть в первую очередь, потому что офлайн это проверить невозможно:
* плавность движения двойника на клиенте;
* езда игрока на движущихся платформах (AlignPosition с `Responsiveness = 60`);
* загрузка внешности двойника (`CreateHumanoidModelFromDescription`);
* вращающиеся балки (анимация на клиенте должна совпадать с серверной проверкой попаданий).

Все значения для подстройки лежат в `Config.lua`.
